# PERIPH-EXTRACT-01E.2/3 — Candidate distribution and compatibility

Candidate 0.1.0-alpha.1 (Python 0.1.0a1); no install/enable/start, deployment, physical commissioning, new privilege or canonical promotion.

## Distribution scope

- Linux x86_64, CPython 3.12 and Rust 1.100.0 are the CI target; other platforms/interpreters are unvalidated. Existing robot interpreters and services are not modified.
- `packaging/build_host_wheel.py` stages an explicit four-file Python source allowlist, the seven exact JSON schemas, MIT LICENSE and metadata. The wheel is pure Python with packaged local schema resources, not a second implementation. It exposes `rgd-periph-broker` and `rgd-periph-control`; neither is invoked automatically at installation/import. Production broker still requires explicit allowlist and initialized recovery state.
- `requirements-host.lock.txt` pins every direct and transitive runtime version from the tested profile; the CI uses wheel-only installation, checks dependencies, records dependency wheel SHA-256, and installs the candidate wheel from a local wheelhouse in a fresh venv. Third-party dependency wheels are not redistributed by this repository. Build tool versions are fixed; release artifact checksums describe bytes observed, not an external signature or supply-chain attestation.
- `Cargo.lock` was generated by Cargo on the tested runner, committed with registry checksums, and the workspace is tested using `--locked`. Rust is a source library, not a host binary. Distribute the entire workspace archive so the external fixture corpus is available; provenance verification against original commits requires a Git clone containing their ancestry.
- CI builds the Python wheel twice in independent staging directories and compares bytes under fixed SOURCE_DATE_EPOCH. Builds the Git source archive twice with deterministic gzip headers, unpacks and runs the locked Rust suite. Fresh wheel import, seven schema resources, recovery journal and mocked status are tested. No service unit, actual allowlist, publisher or installer is included; entry-point help and synthetic smoke only.
- Artifacts: wheel, source tar.gz, dependency-wheel-SHA256SUMS, SOURCE_COMMIT and SHA256SUMS. They identify a candidate build, not a signed release. CI retention is finite.

## Registry compatibility boundary

The current published Registry schema only accepts pinned_git_cargo with an executable binary. PERIPH has a Python service plus a Rust library, with a different local recovery/authorization boundary; do not pretend it is a compatible installable binary. `packaging/module-manifest.candidate.json` is a local distribution descriptor, not a published registry entry or canonical manifest. A separate owner-reviewed extension to the registry distribution/install contract is required. No registry mutation in this PR.

## Release acceptance

Source acceptance requires all CI jobs green on the exact candidate, seven schema hashes unchanged, source provenance ancestor preserved, review of packaging contents and limitations, and one consolidated main. Retain previous Console implementation inactive until version-pinned consumer cutover, explicit rollback plan and physical/authorization gates. A source candidate is not a host release approved for activation. No automatic start on installation.
